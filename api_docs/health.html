System Health & Liveness Probes API

Base Paths: /live or /api/v1/live

Security: Public (No authorization required)

1. Check Service Liveness & Health

Checks real-time application uptime, database connectivity, and backend dependencies health status.

  • Method: GET
  • Path: /live or /api/v1/live
  • Security: Public (permitAll)
  • Headers: Accept: application/json

Success Response (200 OK)

Returned when both the application service and PostgreSQL database are healthy and responding:

{
  "status": "UP",
  "message": "Joppe backend is live and healthy.",
  "timestamp": "2026-10-26T12:00:00Z",
  "version": "1.0.0",
  "details": {
    "database": "CONNECTED",
    "service": "UP"
  }
}

Degraded Response (503 Service Unavailable)

Returned when the PostgreSQL database or a critical dependency is unreachable:

{
  "status": "DOWN",
  "message": "Cannot access backend service dependencies: database is unreachable or degraded.",
  "timestamp": "2026-10-26T12:00:00Z",
  "version": "1.0.0",
  "details": {
    "database": "DISCONNECTED",
    "error": "Connection to database failed: ...",
    "service": "DEGRADED"
  }
}

Method Not Allowed Response (405 Method Not Allowed)

Returned when invoking /live with an unsupported HTTP method (e.g. POST, PUT, DELETE):

{
  "status": "ERROR",
  "message": "Cannot access /live with this HTTP method. Only GET is permitted.",
  "timestamp": "2026-10-26T12:00:00Z",
  "version": "1.0.0",
  "details": {
    "allowedMethods": "GET",
    "error": "Method not allowed for /live probe"
  }
}
