Admin — Orders & POS Management API

Base Path: /api/v1/admin/orders

Controller: joppe.backend.admin.controller.AdminOrderController

Security: All endpoints require ORDER_MANAGE authority

Order State Rules & Business Invariants

  • Sequential Status Transitions: ACCEPTED → PACKAGING → DELIVERY → SHIPPED → REFUND (optional). Cannot move backward.
  • Payment Status: PAID → REFUND. Cannot regress to UNPAID.
  • 10-Day Refund Window: An order cannot be refunded if more than 10 calendar days have passed since payment or completion.

1. List All Orders

Lists orders with status, payment status, and keyword search filters.

  • Method: GET
  • Path: /api/v1/admin/orders
  • Security: Requires ORDER_MANAGE

Query Parameters

Parameter Type Required Description
status string No Filter by order status (ACCEPTED, PACKAGING, DELIVERY, SHIPPED, REFUND, CANCELLED)
paymentStatus string No Filter by payment status (UNPAID, PAID, REFUND)
search string No Case-insensitive search matching order code, recipient name, or phone number

Success Response (200 OK)

Returns array of OrderSummaryResponse objects.

2. Get Order Detail

  • Method: GET
  • Path: /api/v1/admin/orders/{id}
  • Security: Requires ORDER_MANAGE
  • Path Variable: id (UUID)

Success Response (200 OK)

Returns full OrderResponse object with line items and customer details.

3. Update Order Status

Advances the order state forward.

  • Method: PATCH
  • Path: /api/v1/admin/orders/{id}/status
  • Security: Requires ORDER_MANAGE
  • Path Variable: id (UUID)

Request Body

{
  "status": "PACKAGING"
}

Lifecycle Actions

  • Transitioning to SHIPPED: calls deductStockOnFulfillment for all line items.
  • Transitioning to CANCELLED: calls releaseStock for all reserved line items.

Success Response (200 OK)

Returns updated OrderResponse.

4. Update Payment Status

  • Method: PATCH
  • Path: /api/v1/admin/orders/{id}/payment-status
  • Security: Requires ORDER_MANAGE
  • Path Variable: id (UUID)

Request Body

{
  "paymentStatus": "PAID"
}

Success Response (200 OK)

Returns updated OrderResponse.

5. Create Order on Behalf of Customer / Walk-in POS

Creates an order at the store cashier counter (POS). Auto-provisions a customer account if not yet registered so warranty history is tracked.

  • Method: POST
  • Path: /api/v1/admin/orders
  • Security: Requires ORDER_MANAGE

Request Body

{
  "userId": null,
  "customerEmail": "walkin_customer@gmail.com",
  "recipientName": "Tran Van B",
  "recipientPhone": "0912345678",
  "shippingAddress": "Store Counter Pickup (POS)",
  "customerNote": "Paid cash at store counter",
  "shippingFee": 0.0,
  "orderStatus": "SHIPPED",
  "paymentStatus": "PAID",
  "items": [
    {
      "variantId": "22222222-3333-4444-5555-666666666666",
      "quantity": 1
    }
  ]
}

Success Response (201 Created)

Returns created OrderResponse.
